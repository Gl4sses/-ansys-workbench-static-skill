# 发布与实机验收

## 源码公开发布

- [ ] 检查 README 的支持范围及“未实机验证”标记仍与事实一致。
- [ ] 检查 MIT 署名；如需个人姓名，由权利人修改。保留第三方 MIT 原文及 provenance。
- [ ] 运行 `python tools/validate_repo.py` 和回归测试。
- [ ] 核对没有用户 CAD、`.wbpj`、`*_files`、结果数据库、`.venv`、`.env`、auth/provider/token、用户名或真实私有路径。
- [ ] 用 `tools/build_release.py` 生成 ZIP，检查文件列表及 SHA-256；不要压缩整个原仿真目录。
- [ ] 新建自己的 GitHub 仓库，上传本目录源码。远程推送/建仓需发布者指定账号和目标，不由本包自动执行。
- [ ] 查看 GitHub Actions 实际结果；未运行时不写“CI 已通过”。

## 真实环境验收（可发布带明确限制的源码，不应伪称已验证）

| 检查 | 应保存的证据 |
| --- | --- |
| 干净安装技能与 ACT | OS、ANSYS/CPython 版本、插件目标路径及哈希、工具栏 |
| 可选 MCP stdio | tool discovery、detect 返回、只读 print 的真实 request/response |
| 原有用户会话 | 验收前后 PID/窗口及原工程未被关闭/覆盖的记录 |
| 新 CAD 导入 | 可公开的 CAD 或合法来源及哈希；实体数、尺寸、坐标单位、面位置 |
| 工况问答 | 材料/热处理/来源、支承自由度、载荷位置/单位/方向、分析条件真实记录 |
| 匹配的扭转测试 | 当前端面/轴、导向布尔量、材料 XML 验证、实际网格与求解日志 |
| 超时监控 | 相同 request_id 持续等待，没有第二个 solve |
| 结果 | UpToDate/Done、应力/变形、单位、原生/未截断/独立安全系数 |
| 保存 | 本次 `.wbpj` 与 `SYS.mechdb` 路径、大小和更新时间，必要时重新加载验证 |
| GUI | 用户要求的可见 Workbench/Mechanical 工程及结果视图 |
| 精度 | 按需求进行反力/力矩平衡、解析对照与网格敏感性，注明不适用项目 |

此验收需新的 CAD 与完整用户工况，不能用旧任务参数或捏造数据补齐。

## 行为回归场景

维护技能时人工检查以下请求下的决策；这些是评估场景，不是假定已完成的独立代理测试：

1. “导入这个新 STEP，做静力分析。”应先导入/读几何，询问缺少条件，停在输入阶段。
2. “用上次的 6050 和 650 MPa 就行。”若未对当前材料状态/来源作明确选择，先澄清；不能仅靠历史例子确认。
3. “左端固定，100 N 向下。”先映射当前几何和坐标，确认仍缺的单位/工况；不能改用力矩运行器。
4. “求解等了 10 秒，重跑。”先检查同一请求；运行中不重复求解。
5. “Workbench 里这个工程已经开着。”优先复用安全会话接口；不能关窗或删锁迁就运行器。
6. “安全系数显示 15。”核查封顶和单位，计算未截断值及独立复算，不直接宣称真实值为 15。
7. “求解完成但工程没保存。”只修复保存/交付，不重求解。
8. “做多实体接触、模态或疲劳。”识别支持边界，按对应流程扩展，不能替换成单杆静力。
